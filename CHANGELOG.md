# Changelog

All notable changes to this project are documented in this file.
The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [Unreleased]

### Added
- Repository skeleton: SwiftPM `TokenBeCore` package (GRDB 7.12.0), lint rules, build/verify scripts, and the engineering docs (Stage 0.1).
- Logging core: redacted NDJSON log files with rotation and retention, os.Logger mirror, breadcrumbs, and a crash handler that records the last 50 breadcrumbs (Stage 0.2).
- Settings core: every setting from the spec with its default, range checks with logging, threshold ordering, reset, and the log level setting (Stage 0.3).
- The app: a menu-bar glyph with a placeholder popover; launch, quit and crash are logged, and an unclean previous run is detected (Stage 0.4).
- Continuous integration: build, tests, coverage gate, lint, event-table check, app build and a secret/URL guard on every pull request (Stage 0.5).
- Popover: the empty state (`No accounts yet`) and a `Quit` button; shared formatting for money, runway, tokens and freshness (Stage 1.1).
- Dashboard window: `Open dashboard` (⌘D) in the popover, or ⌥-click the menu-bar icon; empty Overview with the `Today | 7 d | 30 d | 90 d` range picker. The range and window position are remembered (Stage 1.2).
- Settings window: `Settings…` (⌘,) in the popover opens General, Privacy and Advanced. Launch at login, menu bar metric, pinned metric, sort, hide cents, appearance, accent, log level and log retention all work. A recordable global shortcut (default ⌃⌥T) toggles the Dashboard (Stage 1.3).
- Database: TokenBe keeps its data in `tokenbe.sqlite` (migration 001, WAL). A corrupt file is moved aside and replaced by the backup, or by a fresh database. If the database cannot be opened or migrated, an alert names the migration, the error and the backup path, then TokenBe quits without touching the file (Stage 2.1).
- Settings → Advanced: `Run integrity check now` shows `ok` or the first problem SQLite found, plus where a copy of the database was saved. `Back up now` writes `tokenbe.sqlite.bak` and shows its size, time and path. The popover's account list now comes live from the database (Stage 2.2).
- Networking core: one HTTP transport with 02's User-Agent, 15/30 s timeouts and a 20 MiB response cap; 04's error taxonomy and retry policy; DEBUG fixture mode; network reachability changes are logged. Nothing visible yet (Stage 3.1).
- Keychain storage for API keys: one login-keychain item per account (service `dev.bathyon.tokenbe`, this device only, never synced), and failures are logged without the key. Nothing visible yet (Stage 3.2).
- Provider seam: provider ids with key-prefix checks, a capabilities model stored as JSON, the adapter protocol, and a registry that offers only verified providers in Release builds. Adds `scripts/record-fixtures.sh` for recording redacted live fixtures. Nothing visible yet (Stage 3.3).
- OpenAI adapter: the probe behind onboarding's "Test connection", and polls for keys, hourly usage (last 48 h, paged, resumable) and daily cost (last 7 days) into the database, with 04's retries, circuit breaker and redacted diagnostics. Built on synthetic fixtures; nothing visible yet (Stage 3.4).
- Add an account: `Add account…` (or the first launch) opens onboarding — pick the provider, paste the key, `Test & continue`, then see the mode, keys found and currency, set the anchor and `Done`. The popover shows the account card (`No data yet`, or `Key missing · Fix…`), the Dashboard sidebar lists accounts, and Settings → Accounts edits the label, tests or replaces the key, pauses, lists Keys & apps and removes the account (Stage 3.5).
- OpenAI verification, first part: the fixture recorder follows every page of usage and costs, anonymizes people and key ids, and records the real 401 body; the response envelope keys seen in the first live recording are now known. OpenAI stays unverified until the owner's row-bearing recording (H2) lands (Stage 3.6).
- Polling runs on its own: usage every 5 min and key lists every hour for OpenAI, set in the new Settings → Sources tab (with the Low Power multiplier) or per account under Accounts → `Refresh intervals`. A new account is polled at once. The popover header shows `Refreshed …` and a refresh button; `Pause polling for 1 h` / `Resume` pause everything, and an account's `Paused` toggle pauses it. Offline, Low Power Mode, sleep/wake, clock jumps and stuck polls are handled and logged (Stage 4.1).
- Stale and offline: a card whose data is older than 3 × its poll interval (`tb.alerts.staleMultiplier`) dims and reads `stale · …`; offline, the popover shows `Offline — showing last known values` and dims every card; either turns the menu-bar ring dashed. Clicking a card, or an account in the Dashboard sidebar, opens the account page: provider, label, mode, band and freshness, `Refresh`, the Balance/Usage/Cost/Lag badges with a help sentence each, and a sources strip with each job's state, last success, next run and the last error in plain words. The Dashboard toolbar has `Refresh`; sidebar rows show `Key missing` (Stage 4.2).
- Daily tasks: once a day, at a time macOS picks, TokenBe polls OpenAI's costs, backs up its database, runs the full integrity check every 7th day and frees unused space; a failing task is logged and retried the next day without stopping the others. Settings → Sources → `Run daily tasks now` runs them at once; Settings → Advanced shows `Last daily run`; the account page's cost source shows the time of its last success (Stage 4.3).
- Price book: TokenBe ships a snapshot of the LiteLLM price map and refreshes it once a day (ETag, 20 MB cap, a feed that changed shape is ignored). Settings → Sources → Price book has the feed switch, `Refresh now`, `Stale after`, and an overrides table with `+`/`−` and `Reset to feed`; Advanced edits the feed URL. Each account page shows `Prices · <date> · ok/stale` (Stage 5.1).
- Cost estimates: every hourly usage row is priced from the price book (05's formula, rounded once). A new snapshot or an override change reprices the last 90 days. The account page shows `Spend today`, `Spend in range` and, when some usage has no price, `Unpriced in range`. The Overview shows `Total spend <range>` for USD accounts, and the Price book line counts unpriced models (Stage 5.2).
- Remaining, runway and bands: anchored accounts show `≈ $N ± M` (anchor + top-ups − spend since the anchor, with 05's estimate band), two runway paces (`~12 d · ~9 d today`), and `Collecting… runway after 2 days of data` until there is a week's burn. Bands follow 05 and the new Settings → Alerts thresholds. The popover shows an alert banner for low, critical or a missing anchor, and ↑/↓/⏎ move between cards. The Overview has the shortest-runway headline, `Total remaining` and the runway board. The account page has `Set anchor…`, `Add top-up…`, Remaining/Runway/Burn 7 d, anchor nudges and the ledger. Accounts has auto-reload (`reloads at $X`). Band changes are stored and logged (Stage 5.3).
- Notifications: macOS notifies when an account turns low or critical, when an anchor has been missing for a day, and when data has been stale for 6 hours. Each has its own switch, and an account gets at most one per kind a day. Quiet hours (default 23:00–07:00) hold notices until they end, and the notification's `Open` and `Snooze 24 h` work. Permission is asked at the first alert; if it is denied, Settings → Alerts says so with `Open System Settings`. `Send test notification` is in the same tab (Stage 5.4).
- Menu bar: the ring is notched while any account is low or critical (dashed still wins for stale or offline), from launch on, using the last stored bands until the first polls. The metric chosen in Settings → General shows beside it: `12d`, `$42` or `$3.10` (Stage 5.5).
- DeepSeek: add an account with a standard API key. Its balance is read directly every 60 s, in CN¥ or $, without `≈`. An account the provider reports unavailable is shown critical, with `Provider reports account unavailable` on its page. The Overview totals count CN¥ accounts as `+ N non-USD`. Offered in Debug builds until its live recording exists (Stage 6.1).
- xAI: add an account with a standard API key. If xAI reports a remaining balance, it is read directly every 60 s. Otherwise the account is anchored, and onboarding asks for the balance shown on the billing page. Offered in Debug builds until its live recording exists (Stage 6.2).
- Apps: an OpenAI account's page shows a **By app** table — each key's requests, tokens, spend and share, with a `Total` that equals the account's spend. Name a key with `Name…`, or bind keys to apps in Settings → Accounts → Keys & apps (`Bound app`, `New app…`). The Overview lists `Apps this period`, the sidebar's `Apps` page edits app names, and each popover card can show today's top apps. The account page's Sources strip now wraps to the window. UI-test runs now cover only the suites a change touches (Stage 7.1).
- Harness reports: append one JSON line per request to a file in `~/Library/Application Support/TokenBe/ingest/` and TokenBe attributes the spend to your app within seconds — the only per-app source for DeepSeek and xAI, and a per-key split for OpenAI. Duplicates are ignored, a crash never double-counts, finished files move to `ingested/` and bad ones to `rejected/`. Settings → Sources → Harness reports shows the folder, status and today's counts, and copies a Python or Node reporter; the README has both. DeepSeek and anchored xAI accounts get burn and runway from harness spend (USD accounts), a single-app DeepSeek account's balance drop is attributed to it, and drift against the balance is logged daily (Stage 7.2).
- Drilldown: click an app under the Overview's **Apps this period** to open its account page filtered to that app (`App: <name>` chip, ✕ to clear). A DeepSeek or xAI page shows `Harness drift · <day> · ±$N` when a closed day's harness lines and balance drop disagree beyond the Alerts drift threshold. Usage with no app is the `Unassigned` row everywhere (Stage 7.3).
- Account page: the **By model** table lists each model's requests, tokens by class, estimated cost, the provider's cost and the drift between them. Drift beyond the Alerts drift threshold is flagged, and a model missing from the price book reads `unpriced` instead of a price. A daily check logs `ledger.drift` for yesterday's drifting models (Stage 8.1).
- Overview: the **Spend by day** chart stacks each USD account's daily spend over the range in its own colour; hover a day to see each account and the total. The **Cache savings** tile shows `Saved $X via cache (net of writes)`, with one line per account; OpenAI reads `—` because its aggregate cache counts are unreliable (Stage 8.2).
- Dashboard toolbar: **Export…** saves the table on the current page as a CSV file. The Overview saves the runway board, an account page its By-app table (only the filtered app's rows when a filter is set), and the Apps page the apps list. Each cell is written as the page shows it (Stage 8.3).
- Accessibility: VoiceOver reads every amount and runway in words with its title (`Remaining, approximately 42 dollars, plus or minus 3`) and names the band wherever colour shows it. The popover's cards grow with the text size up to xxLarge. Under Reduce Motion the refresh button and every spinner pulse instead of turning. The Dashboard's tables take keyboard focus (↑/↓ between rows, Esc to leave). The Spend by day chart exposes each day's total without hovering (Stage 8.4).
- Retention roll-ups: the daily run sums hourly usage older than 90 days into daily rows, daily rows older than 400 days into monthly rows, deletes raw harness events after their window and keeps two balance snapshots per day after a week; Advanced sets the two windows (`Hourly detail kept for`, `Raw harness events kept for`). Older days keep their totals and cache savings (Stage 9.1).
- Data export and import: Advanced → `Export data (JSON)…` writes every account, key, app, usage, cost, balance, ledger and price-override row; `Import…` reads such a file into an empty database; `Export CSV (all tables)…` writes one CSV per table. Keys are never exported (Stage 9.2).
- Diagnostics: Advanced → `Export diagnostics…` saves a zip with the last 3 log files, recent log records, settings, the database schema and row counts, poll state (redacted), price overrides and the environment. It never includes the database or any key (Stage 9.3).
- Update check: once a day TokenBe asks GitHub for the latest release; when it is newer, Privacy, the Overview and the popover show `Update available` with the release page and `Skip this version`. Privacy → `Check for updates daily` turns it off. Nothing is downloaded or installed (Stage 9.4).
- Reset and environment: Advanced → `Reset all settings…` (after a confirm) returns every setting to its default, keeping onboarding, keys and data. A time-zone change while running is handled without extra polls, and the log file still turns over at local midnight (Stage 9.5).
- Dashboard sidebar: `+` and `−` at its foot. `+` adds another provider's account (the same Add account steps), `−` removes the selected account after the usual confirm. Verification gains `TB_SOAK=1`, which skips UI tests and app launches while the 14-day soak runs on the same Mac (Stage 10.0.1).
- xAI: accounts now use an xAI management key and read the team's daily spend from xAI's Management API, so the runway works from your anchor. The old inference-key check returned no balance. TokenBe calls only the key-validation and usage endpoints (Stage 10.0.2).
- Database: migration 002 lets an account belong to the new providers (Moonshot, Novita, StepFun, SiliconFlow, DeepInfra) and keeps every existing row. Exports made before it still import (Stage 10.0.3).
- Moonshot (Kimi): add a Moonshot account with its API key; TokenBe finds the key's region (international in USD, China in CNY) and shows the balance directly (Stage 10.0.4).
- Novita: add a Novita account with its API key and see its balance directly. The provider picker scrolls once there are more tiles than fit (Stage 10.0.5).

### Changed
- The test coverage gate for the core library is now 97 % of lines, up from 85 % (Q-035).

### Fixed
- A poll stopped while it was writing (account removed, app quitting, overrun) no longer logs a `poll.failed` error.
