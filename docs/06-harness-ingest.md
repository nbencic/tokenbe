# 06 — Harness reports (JSONL drop folder)

Purpose: give per-app attribution where the provider cannot (DeepSeek, xAI) and per-request detail everywhere else, WITHOUT a proxy. The user's harness appends one JSON line per completed request to a file in the drop folder. TokenBe tails the folder.

## Folder layout (fixed; created at first launch)

```
~/Library/Application Support/TokenBe/ingest/            ← user drops/appends files here
~/Library/Application Support/TokenBe/ingest/ingested/    ← files moved here after EOF + quiescence AND the user enabled "move when done" (default ON)
~/Library/Application Support/TokenBe/ingest/rejected/    ← files whose first non-empty line is not valid v1 JSON
```
Accepted file names: `*.jsonl` and `*.ndjson` directly in `ingest/` (no recursion). Hidden files (`.`-prefixed), symlinks and directories are ignored and logged `ingest.skipped` once per path.

## Line format — version 1 (REQUIRED exact shape)

```json
{"v":1,"ts":"2026-11-09T14:03:21.512Z","provider":"deepseek","app":"weather-collector","key_hint":"sk-…a9f2","request_id":"c7c3e2a4-…","model":"deepseek-chat","usage":{"prompt_tokens":1532,"completion_tokens":212,"prompt_cache_hit_tokens":1200,"prompt_cache_miss_tokens":332},"status":"ok"}
```

| Field | Type | Required | Rule |
|---|---|---|---|
| `v` | int | yes | must equal `1`; other values → line rejected `ingest.bad_version` |
| `ts` | string | yes | RFC 3339 with `Z` or offset; parse failure → line rejected |
| `provider` | string | yes | one of `openai`, `anthropic`, `openrouter`, `deepseek`, `xai` (lowercase); other → line rejected `ingest.unknown_provider` |
| `app` | string | yes | 1–64 chars, regex `^[a-z0-9][a-z0-9._-]{0,63}$` after lowercasing; else rejected `ingest.bad_app` |
| `key_hint` | string | no | last 4 chars of the API key used, optionally prefixed with `…`. Only the LAST 4 chars are stored (`harness_event.key_hint`); matched against the last 4 chars of `provider_key.redacted`. Anything longer than 12 chars is truncated to the last 4 and logged `ingest.key_hint_truncated` once per file. |
| `request_id` | string | yes | provider's request id if available, else a UUID generated by the harness; 1–128 chars; dedup key |
| `model` | string | yes | as returned by the provider |
| `usage` | object | yes | provider's `usage` object VERBATIM (see 05 normalizers); stored as `usage_json` |
| `status` | string | yes | `ok` or `error`; `error` lines store usage if present and are counted in `requests` but flagged `status='error'` |
| `cost_cents` | int | no | if present and `provider == "openrouter"`, used as the line's cost instead of the price book |

Unknown top-level fields are ignored and logged `ingest.unknown_fields` once per file per field name.

## Tailing algorithm (deterministic)

1. At launch: scan `ingest/` for accepted files; for each, load its `ingest_file` row by `path`. If the row's `inode` differs from the current inode → treat as a NEW file (offset 0, log `ingest.inode_changed`). If `last_size > current size` → file was truncated → reset offset to 0, log `ingest.truncated`.
2. Register an FSEvents stream on `ingest/` with latency `1.0` s and flags `kFSEventStreamCreateFlagFileEvents | kFSEventStreamCreateFlagUseCFTypes | kFSEventStreamCreateFlagNoDefer`. Callback → `IngestService.fileChanged(path)`.
3. `fileChanged(path)`: open the file, seek to the stored `offset`, read to EOF in 64 KiB chunks. Split on `\n`. The final fragment WITHOUT a trailing `\n` is NOT processed; the offset stops before it (handles partial writes). Each complete line → `processLine`.
4. After processing, write `offset`, `last_size`, `last_mtime` to `ingest_file` IN THE SAME TRANSACTION as the inserted `harness_event` rows (invariant V7 in `04` — a crash cannot double-count).
5. Quiescence: if a file's mtime has not changed for `2.0` s after the last read reached EOF, AND the setting `tb.ingest.moveWhenDone` is true, AND the file is not open by another process (check via `fcntl(F_GETPATH)` is NOT reliable → use `lsof`-free heuristic: attempt `open(O_WRONLY|O_EXLOCK|O_NONBLOCK)`; success means nobody holds it) → move to `ingested/` with a `.YYYYMMDD-HHMMSS` suffix inserted before the extension; set `state='ingested'`. If the lock attempt fails → leave in place and retry on next change event (harness keeps appending to it; this is the normal long-running case).
6. A file whose first non-empty line fails JSON parsing or fails the `v == 1` check → move whole file to `rejected/` immediately, `state='rejected'`, log `ingest.file_rejected` with the first 200 bytes (redacted).

## processLine (exact)

```
parse JSON → on failure: ingest_file.lines_rejected += 1; log ingest.bad_json {file, line_no}; continue
validate fields per table → on failure: lines_rejected += 1; log the specific event; continue
INSERT OR IGNORE INTO harness_event (provider, request_id, …)
   if the insert was ignored (duplicate): lines_duplicate += 1; log ingest.duplicate at .debug; continue
resolve app:    app row by name (case-insensitive) → create if missing (log ingest.app_created)
resolve binding: app_binding (kind='harness_tag', value=app.name, account=provider account) → create if missing
resolve key:    if key_hint present and exactly one provider_key of the account has redacted ending in last4 → set harness_event.provider_key_id (ambiguous → NULL + log ingest.key_hint_ambiguous)
normalize usage → classes_json (05) or NULL + log normalize.failed
price → est_cost_cents, unpriced flag (05); for openrouter prefer cost_cents field
UPSERT usage_bucket (source='harness', bucket_width='1h', bucket_start = floor(ts to hour UTC), model, provider_key_id, service_tier='standard')
```

## Attribution precedence (per account, per period)

1. If the account's provider gives per-key usage (`capabilities.perKeyUsage == true`: openai, anthropic, openrouter): **provider rows are truth**. Harness rows are used ONLY to split a provider key's total among apps bound to that key via `harness_tag`, proportionally by harness `est_cost_cents` (fallback: by total tokens). The per-app values are displayed with the "≈ split" badge. Σ(apps) == provider key total, always; rounding remainder goes to the largest app.
2. If the provider gives balance but no usage (deepseek, xai without usage): harness rows are the ONLY source of spend, displayed with the "harness" badge. Balance deltas are used for reconciliation only: if `Σ harness est_cost` over a closed day differs from the day's balance delta by more than `drift_threshold`, the account page shows the drift chip and logs `ledger.harness_drift`.
   Single-app inference (decision D-deepseek-single-app = ON): if an account has exactly ONE harness app and NO topup in the day, the balance delta is attributed to that app with badge "inferred" when harness lines are absent for that day.
3. Harness rows NEVER add to provider spend. They split or substitute. Never both.

## Reporter snippets (ship in `docs/reporters/`, copied verbatim into the repo README)

Python:
```python
import json, os, time, uuid
P = os.path.expanduser("~/Library/Application Support/TokenBe/ingest/harness.jsonl")
def report(provider, app, model, usage, key, request_id=None, status="ok"):
    line = {"v": 1, "ts": time.strftime("%Y-%m-%dT%H:%M:%S", time.gmtime()) + "Z",
            "provider": provider, "app": app, "key_hint": key[-4:],
            "request_id": request_id or str(uuid.uuid4()), "model": model,
            "usage": usage, "status": status}
    with open(P, "a", encoding="utf-8") as f:
        f.write(json.dumps(line, separators=(",", ":")) + "\n")
```
Node:
```js
const fs = require("fs"), os = require("os"), path = require("path"), { randomUUID } = require("crypto");
const P = path.join(os.homedir(), "Library/Application Support/TokenBe/ingest/harness.jsonl");
function report(provider, app, model, usage, key, requestId, status = "ok") {
  const line = { v: 1, ts: new Date().toISOString(), provider, app, key_hint: key.slice(-4),
    request_id: requestId || randomUUID(), model, usage, status };
  fs.appendFileSync(P, JSON.stringify(line) + "\n");
}
```
Rules for reporters (stated in README): append only; one `write` per line (atomic for lines < 4 KiB on APFS); never rewrite or truncate the file; rotate by creating a new file name, never by truncating.

## Failure handling (all logged — see 07)
| Case | Behavior | Log event |
|---|---|---|
| Folder missing at launch | recreate; log | `ingest.folder_recreated` (warn) |
| File moved to `ingested/` or `rejected/` | — | `ingest.moved` |
| Folder not writable | disable ingest; Settings → Sources shows red status | `ingest.folder_unwritable` (error) |
| FSEvents stream fails to start | fall back to 30 s directory poll | `ingest.fsevents_failed` (error) |
| File > 512 MiB | process but log warning; recommend rotation in UI | `ingest.large_file` |
| Line > 64 KiB | reject line | `ingest.line_too_long` |
| Burst (> 10 000 lines in one read) | process in 1 000-line transactions | `ingest.burst` |
| Clock skew: `ts` > now + 5 min | accept, store, flag `future_ts=1` | `ingest.future_ts` |
| `ts` older than retention horizon | store event, skip bucket upsert | `ingest.too_old` |
| Same `request_id` with different usage | first wins; log | `ingest.duplicate_conflict` (warn) |
| Permission error reading a file | skip, retry on next event, max 5 then mark `state='rejected'` | `ingest.read_failed` |

## Definition of done
- E2E-3 (11): append 500 lines in bursts while the app runs → 500 `harness_event` rows, 0 duplicates, offsets correct; `kill -9` mid-write then relaunch → still 500.
- Rejected file lands in `rejected/`, UI shows count.
- Attribution tests: split (OpenAI key with 2 apps), substitute (DeepSeek), inferred (DeepSeek single app).
